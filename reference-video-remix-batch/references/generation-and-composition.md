# Seedance 生成调度与 30 秒合成

确认包已经获用户明确确认后读取本文件。这里规定真实调用、分波、恢复和最终音视频合成；不能用计划或 dry-run 冒充执行。

## 执行前门槛

开始真实生成前逐项满足：

1. 批次格式与数量校验通过。
2. 当前批次逐资产授权和所需上传确认完整。
3. 每个待调用 segment 引用已确认、哈希匹配的不可变确认包。
4. 当前环境存在真实 Seedance 视频 Tool，并能明确选择 `seedance_2.5`。
5. Tool 能接受每条独立的提示词与参数，并能返回可跟踪的提交结果。
6. 已生成媒体能力探测报告，合成和必检路径可用或已明确暂停。

若 Tool 自身强制每次调用都等待人工确认，就停在计划阶段，说明无法兑现“一次确认后批量执行”。不要通过嵌套调用 `seedance-25` Skill 或 UI 自动点击绕过确认。

## 调用契约

对每个 segment 逐字提交其 `prompt_text`，工具参数来自独立 `invocation_spec`。强制检查：

- `model_version` 为 `seedance_2.5`。
- 时长为 5–30 秒整数。
- 画幅是允许枚举之一。
- 素材 ID、角色和处理目的地与确认包一致。
- `prompt_hash` 和 `invocation_hash` 在提交瞬间仍匹配。

工具不存在、版本不符、参数 schema 不兼容或素材上限不明时暂停，不编造调用结果。记录 Tool 实际暴露的 `submit`、`query`、容量、幂等或对账、超时、重试等待和取消能力。

## 校准任务

新参考、新风格、复杂多人、遮挡、快速动作、密集文字、复杂卡点或曾出现系统性质量问题时，从当前批次选择一个正常任务作 `is_calibration: true`。它属于已确认集合，计入任务数与生成调用数，不能额外添加隐藏样片。

校准任务须先完成其全部 segment、合成和必检。失败若需要修改公共模板或提示词，同模板尚未提交的任务进入 `AWAITING_REVISION_CONFIRMATION`；生成新确认修订后才能继续。已有同模板的有效合格证据且主体替换简单时，可以直接分波。

## 自适应分波

调度目标是质量、稳定性和总完成时间，不以额度为默认节流理由。

浏览器读取参考始终串行。生成调度按实际适配器类型处理：

- UI：并发从 1 开始。首个生成调用成功后，如仍有至少两个待提交调用，只做一次双任务探测；两者均有独立任务 ID 且无平台/参数失败时，上限升为 2。没有进一步的明确容量证据时不超过 2。
- API：必须有公开或账户返回的 `reported_capacity`。初始并发为 `min(4, reported_capacity)`；健康波次后可翻倍，但不得超过该容量。
- 本地合成：使用独立队列，初始并发 2；出现内存、磁盘或编码错误后降到 1。

健康波次要求所有提交都有唯一任务 ID、全部到达生成成功终态、无认证/限流/参数/不确定提交错误且未超标称超时。质量是否通过由校准门和 QA 处理，不把它误作平台容量证明。

出现限流、队列压力或不确定提交时并发减半，最低 1；优先采用工具给出的 `retry_after`，缺失时用 60 秒。连续三次退避后暂停生成阶段并汇报，不无限等待。

## 提交与对账

每次真实提交遵循：

1. 从已确认 segment 读取两个哈希。
2. 建立唯一 `client_submission_id`。
3. 把 ID、`SUBMITTING` 和提交时间原子写入私有状态。
4. 调用 Seedance Tool。
5. 明确接受时记录唯一任务 ID，转为 `SUBMITTED`。
6. 拒绝时记录结构化原因，不假装已排队。
7. 结果不确定时转为 `NEEDS_RECONCILIATION`。

恢复时按任务 ID、客户端 ID或用户可见任务列表查询。没有可靠查询或对账时，一次只提交一个可见任务；无法确定是否已提交就暂停让用户决定，不能盲目重投。

适配器未报告标称超时时，单个生成任务 30 分钟未到终态则进入 `NEEDS_RECONCILIATION`，不是自动失败或重投。只能在 Tool 实际支持取消且返回确认后声称已取消。

## 技术重试和质量修订

网络中断、明确排队失败或无结果的瞬时错误，可用完全相同的提示词、模型、参数、素材和两个哈希自动技术重投一次。重投前仍要走提交前落盘和对账逻辑。

头部比例、身份、视线、动作、旧人物残留、文字留白或氛围不对属于质量问题。需要改提示词、参数或素材时：

1. 标记 `AWAITING_REVISION_CONFIRMATION`。
2. 生成新的提示词/调用哈希和确认包修订。
3. 完整展示受影响调用。
4. 用户确认后再提交。

只有初次确认包已完整列出精确重试版本及唯一客观触发条件时，才可自动使用那个版本。技术重投一次或一个已确认质量版本仍失败时标记 `FAILED_FINAL`，继续其他任务。

## 分段策略

仅当单次限制、复杂结构或质量收益足以支撑时分段。分界应落在完整镜头、遮挡转场或音乐结构边界，避免持续动作、对白或乐句中间硬切。

每段记录：实际提交时长、目标时间范围、源时间线范围、衔接动作、服装、色调、构图和主体一致性。目标镜头不足 5 秒时，与相邻镜头合并，或生成至少 5 秒的带余量片段后按时间线裁切；确认包展示实际提交时长。

一个 30 秒任务拆为两段就是两次 Seedance 调用。所有调用都必须在确认集合中，批次总调用数随之增加。

## 视频合成

生成片段成功并核验内容哈希后，按 `media_operations` 无环依赖图执行：

1. 探测输入媒体。
2. 统一分辨率、帧率、像素格式、编码和画幅。
3. 按 `timeline_map` 裁切、轻微变速或补帧。
4. 在安全边界拼接。
5. 叠加确定性文字。
6. 构造并替换连续主音轨。
7. 合流到最终容器并重新探测。

最终时长必须为 30 秒，容差不超过 2 帧。接缝前后检查黑帧、闪白、重复帧、旧主体闪回和动作跳变。避免用明显变速隐藏大幅时长差。

需要非人物区域像素级不变时，只能选择已验证、获授权的局部替换/合成工具；单纯 Seedance 重生成只能按相似度验收目标交付。

## 连续音轨和稳定文字

需要保留音乐或音乐转场时，默认丢弃全部生成片段自带音频。先完成整条画面，再从 0 秒铺设按 `timeline_map` 构造的一条连续、已授权主音轨。音乐不能在每个 segment 开头重启。

仅混入清单明确列出的对白、环境音和音效，并记录来源、时间段和增益。有意静音需在时间线中明确标注。音轨不足 30 秒时不要擅自循环；请用户提供足长文件或确认具体延展方案。

重要标题、品牌、专辑名和缩写使用确定性文字叠加：

- 使用清单中的精确字符串、大小写、空格和标点。
- 固定字体、字号、位置、安全区和起止时间。
- 检查出现首帧、持续中段和消失前最后一帧。

这样处理 `ALBUM TITLE`、`ABCD` 等重要文字，避免模型生成后半程变形。文字层修复不需要重生成已通过的视频画面。

## 失败与恢复

- 认证失败：按 Tool 返回的任务、波次或账户作用域暂停，不擅自扩大或缩小范围。
- 音乐缺失：画面可继续，但音频合成暂停；需要保留音乐的任务不得成功。
- 本地确定性操作失败：在输入和参数哈希不变时可安全重跑，不消耗生成重试。
- Cloud 媒体提交不确定：先对账再决定，不重复调用。
- 个别任务终止失败：批次进入 `PARTIALLY_COMPLETED`，交付其他成功项。
- 应用关闭：状态留在私有文件；下次用户调用时从持久状态与下游查询恢复，不声称后台仍运行。

恢复完成后只执行依赖已满足的下一项。不要仅凭阶段名称或聊天记忆推测工作已完成。
